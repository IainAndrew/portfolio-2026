How I work

AI is central to how I work, not an occasional helper. Cursor is my environment, wired to Jira and GitHub so that planning, coding and review share one context, and I usually have several tasks running in parallel across the arc of a piece of work: picking up and writing tickets, scoping, investigating bugs, pressure-testing ideas, reviewing code, drafting docs. I treat it as a discipline rather than a shortcut: I verify what it produces.

In 2026 I took on a lot of backend work in parts of a Rails codebase I had never touched. I used agents to map the code and its conventions, draft first-pass implementations and migrations, and check my approach against how the rest of the codebase already did things. Every output was a draft to verify, and backend engineers reviewed what I shipped. The result was substantial backend features delivered far faster than ramping up cold, to a standard that fit the existing patterns, so the squad was never blocked waiting on a specialist.

I have turned those workflows into team infrastructure, the agent configuration our repositories run on, and shipped AI inside the product itself: the transcription-and-translation pipeline behind course captions in 27 languages. I have shipped LLM-backed features on the product side; I have not yet owned the model side, and I would like to.
