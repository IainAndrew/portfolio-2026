How I work

My day-to-day workflow is built around coding agents. I work in Cursor, wired up to Jira and GitHub so my tickets, codebase, and pull requests all sit in the same context. Most days I have a few agents running in parallel across whatever needs doing: scoping features, writing or picking up tickets, hunting down bugs, bouncing ideas around, reviewing code, or drafting docs. Agents write most of my code now, which means my job is being strict about how the problem is framed and verifying everything they produce before it ships.

Working this way has completely changed what I can take on. In 2026 I picked up a lot of backend work in parts of a Rails codebase I'd never touched before. I used agents to map out the existing code and its conventions, draft initial implementations and database migrations, and double-check my approach against how the rest of the repo worked. I treated the output as a first draft to pull apart and verify, and had backend engineers review my PRs before merging. I ended up shipping substantial backend features in a fraction of the time it would have taken to ramp up cold, in a style that fit right in with the existing codebase, and our squad never had to sit around waiting on a backend specialist.

Beyond my own workflow, I built the shared agent configuration that Pexels' repositories run on, and shipped AI features in the product itself, including the transcription and translation pipeline that generates course captions in 27 languages. Everything I've built with LLMs so far has been on the application and tooling side. I haven't worked on the model side yet, and I'd love the chance to.
